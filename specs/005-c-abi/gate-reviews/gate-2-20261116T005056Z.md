## Findings per principle

**I. Performance and memory first: complies.**
- **Allocations**: the plan's allocations are O(number of cones), O(number of raw parameters) and
  O(number of names), made lazily; NaN-filling costs O(m + n + k) writes. They are listed with
  reasons in Complexity Tracking (plan.md:301-307).
- **Slice bounds**: T013 bounds every slice (`len · size ≤ isize::MAX`) and rejects overflow of
  `n + 1`.
- **Zero copy**: T013 has a positive control that every slice keeps the caller's address.
- **Solver configuration audit**: research R9. The only new parameter is `SoftMemLimit`, and its
  vendor default (Infinity) is kept.
- **Validation**: no validation is removed.

**II. Testing, benchmarks and behavioural evidence: violated. See V3 and V4.**
- **What complies**:
  - Both tiers are planned (quickstart.md steps 1-2).
  - Licensed tests must skip visibly (tasks.md:8-10).
  - Benchmarks for SC-002 and SC-003 are in T021.
  - The C programs are real callers linked against the built libraries (T010, T016).
  - The comparison rule is implemented once in `tests/common/compare.rs` (T010).
- **Gaps**:
  - SC-006 asks for *every* C-expressible invalid-input case. T012 tests only "representative"
    Rust-API invalid inputs.
  - Some C-interface behaviours have no test task: the solver-error code, the name functions, and
    a wrong-length output buffer through C (V3).
  - The new comparison rule is never shown to reject a real disagreement (V4).

**III. Bounded diagnostics and preserved statuses: complies.**

  standard error stay empty, including after the forced panic.
- **Statuses and errors**: raw statuses are exposed (contract:226-227). The vendor's error code is
  available through `optsolver_last_error_solver_code`. The silent hook does not suppress errors:
  a panic still becomes `OPTSOLVER_ERR_INTERNAL` with its message.

**IV. Zero-copy borrowed inputs and bulk native calls: complies.**

## Observations (not violations; route to implementation or closeout)

- **O1. Naming (XII-C, XII-A).**
  - Gate 2A observation O1 recommended renaming `optsolver_csc`'s `m, n`. ABI 1.0 freezes them,
    and for F the field `m` holds k.
  - The alternative was to add the question to the notation decision routed to the maintainer.
  - Neither was done, and the review-8 row in human-loop.md:39 records only the parameter-name
    part.
  - Also, `optsolver_caps_free(optsolver_caps *c)` (contract:265) still uses `c`.
  - **Recommendation**: rename the parameter, and either rename the fields to `rows`/`cols` before
    T008 or add `m`/`n` to the maintainer's notation item in human-loop.md:55-59.
- **O2. Visible skips for licensed unit tests.** These tests need a licence but sit in standard
  `#[test]` unit tests or in an unspecified file:
  - the read-back test in `src/gurobi/params.rs` (T004);
  - the concurrency test and the move-between-threads test (T006).

  Standard libtest cannot mark a test ignored at run time. The existing pattern
  (`src/gurobi/params.rs:357`, `.expect("Gurobi environment (licence required …)")`) panics, which
  is Gate 2A observation O5. Place these tests in a `harness = false` integration test, so they
  meet tasks.md:8-10 and Principle II.
- **O3. "Before any solver call" evidence.** T012 asserts invalid input fails "before any solver
  call". Use `optsolver_environments_created` (unchanged) or a build with the backend compiled
  and no licence to show it, rather than inferring it.
- **O4. Smaller test gaps to fold into T012 and T017.**
  - Neither index width given while nnz > 0.
  - Overflow of `n + 1`.
  - Standard output and standard error empty on every licensed trial (plan.md:110). T017 does not
    say so.
  - The plan's `dhat` allocation-count check (plan.md:129-130), not named in T021.
  - The informational wall time of the reuse sequence and the one-shot solves (SC-004), not named
    in T018.
- **O5. Enum-code translation in `src/capi/`.**
  - data-model.md:28-32 says each C code is translated by one function, total over the Rust
    enums.
  - A licence-free code-by-code test of those translations would complete II. It could sit in

## Violations (each must be repaired; a new fresh-context reviewer then reviews)

- **V1. Three specified behaviours have no planned check (Principle II: "Every behavioural change
  MUST include the narrowest practical check"; Development Workflow: tasks cover the requirements).**
  In each case the task implements the behaviour but lists no test of it.
  - **(a) The NaN rule of the caller-buffer path.**
    - Where it is required:
      - spec.md:89-94 (Clarifications);
      - spec.md:290-294 (Edge Cases);
      - FR-006 ("with the NaN rule of the Clarifications");
      - contract:202-206 ("fills each supplied array with NaN — before the call, so on any error
        return the supplied arrays hold NaN").
    - T008 lists "NaN fill" as implementation, but its tests check only the error code and name
      for a wrong-length buffer (tasks.md:78-84).
    - Gate 2 review 1, V3(b), asked for "every supplied array NaN". That part of the repair was
      dropped.
    - The comparison trials do not test it either. The comparison rule speaks only of arrays
      "missing in both" (spec.md:117), and on the buffer path every array is present.
    - **Repair**: in T008, assert that every supplied array holds NaN after an error return (the
      wrong-length case). In T010 (buffers, infeasible or unbounded toy), assert that each
      quantity the backend does not return reads back as NaN.
  - **(b) Per-thread error messages (FR-010: "a failure on one thread or handle MUST NOT
    overwrite the message another is reading"; contract:45-47).**
    - T005 implements "per-thread last error", but no test shows that two threads keep separate
      messages.
    - **Repair**: add a licence-free unit test to T005. Fail on two threads with different
      inputs, then check that each thread reads its own message (and its own vendor code).
  - **(c) A compiled-in backend that is not usable (FR-017: "whether it is usable now (with the
    reason when not)"; Edge Cases spec.md:299-301; contract:268-270).**
    - T007 tests only the not-compiled case (UNSUPPORTED) and the usable case with an empty
      reason (tasks.md:73-77).
    - The not-usable path has no test. That path is `OPTSOLVER_OK`, `optsolver_caps_usable` = 0,
      the reason set to the vendor message, and environment creation returning
      `OPTSOLVER_ERR_SOLVER` with that message.
    - **Repair**: add a trial to T007 that runs the C driver as a subprocess with the backend's
      licence variable pointing to a nonexistent file. Alternatively, if that cannot be made
      reliable, state in T007 that the behaviour is recorded as unverified, as Principle II
      requires where execution is unavailable.

- **V2. The cross-artifact analysis still overstates coverage, and its file scope is wrong (VI:
  every decision traceable; workflow.md Bundle 2 step 4; review 1 V6 not closed).**
  - The coverage table maps three requirements as covered when they are not:

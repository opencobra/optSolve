## Observations (not violations)

- **O-1, regression-record scope.** The record compares only `iDopaNeuroC_problem_LP` with `usize`
  indices, 2 of the 8 instance × index-width rows per bundle, and omits solve medians (review 3
  asked for them). I compared all eight rows: heap peak during load identical in every row
  (78 536, 16 384, 47 072, 11 768, 23 536 B, zero spread); overhead ratio under 0.05 in every row
  (largest change Gurobi minNorm `usize` 0.009 → 0.011); solve medians unchanged or faster within
  spread (for example MOSEK minNorm `usize` 8.10e-2 → 8.35e-2 s, spread 6.99e-2–8.69e-2 in 003).
  No regression; extending the record to all rows would make it self-standing. The gate summary
  line "default bench (regression check): ok" means the benchmark ran; the comparison itself is
  in `human-loop.md`.
- **O-2, "recorded so far".** `human-loop.md:80` says "all nine alternating bundles recorded so
  far"; when it was written twelve existed (three at `da7bf81`). The range −5.44 to +1.00 ms is the
  same over nine and over twelve, and the three newest are reported in the next paragraph.
- **O-3, `struct_size` read.** `struct_size` (`problem.rs:264`) uses an aligned `read()`, while
  `options` fields are read with `read_unaligned`; a misaligned options pointer would be undefined
  behaviour at the size read. The header's contract requires valid structures, so this is a
  hardening note.
- **O-4, partial NaN-fill.** `optsolver_solve_into` NaN-fills each buffer as it is checked; if a
  later buffer fails, earlier ones are filled and later ones untouched. The header says every
  supplied array is filled "also on an error return". Carried from review 3's observation on
  validation order.
- Carried over: Gate Reviews table rows after prose in `human-loop.md`; the unreachable `cols + 1`
  overflow branch; `f005::t014` not asserting `SoftMemLimit` in the effective parameters; private
  helpers `env_ref`, `with`, `utf8` dereferencing raw pointers under their callers' contracts;
  the pending human decisions.

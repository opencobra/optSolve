### III. Bounded Diagnostics And Preserved Statuses

**Defect (finding 1).** The design says the C layer prints nothing (plan.md:111) and the test
plan requires the C driver's standard error to be empty on every trial (plan.md:108-109;
FR-018, spec.md:404). Panic containment is `catch_unwind` at every entry point (plan.md:87-88;
research R4; ADR-0004 decision 4). `catch_unwind` does not stop Rust's default panic hook, which
writes `thread '…' panicked at …` to standard error before unwinding begins. So every contained
panic, including the deliberate `optsolver_test_panic` trial that the error-handling criterion
(SC-006) requires, writes to standard error. Nothing in the plan, research, contract or ADR
(searched for "hook", "stderr" and "standard error") addresses this. Either the no-output test
fails on the panic trial, or that trial is exempted without a record. Preventing the output means
replacing the panic hook, which is process-wide for the Rust runtime the library carries. That
affects every Rust panic in the host process (or in a Rust program linking the rlib with `capi`
enabled), so it is a durable boundary decision that belongs in ADR-0004, not an implementation
detail.

Otherwise conforming: messages are returned as data; raw statuses are exposed; the vendor code is
available through `optsolver_last_error_solver_code`.

### Violations and repairs

1. **Contained panics still write to standard error (III, FR-018, VII-C; ADR-0004 decision 4
   incomplete under XIII-C).**
   - *Defect*: `catch_unwind` does not suppress Rust's default panic hook, which prints to
     standard error. The planned no-output test (plan.md:108-109) cannot pass on the forced-panic
     trial (SC-006), and real internal panics would print from the library.
   - *Repair*: decide the mechanism and record it in ADR-0004 and research R4, with its
     process-wide consequences. One way: install, once, a panic hook that is silent and records
     the message when a thread-local "inside a C entry point" flag is set, and that otherwise
     delegates to the previously installed hook, so panics outside the C interface (in a host
     Rust program linking the rlib) behave as before.
   - State the effect in each case: the static library, the shared library, and a Rust
     program linking the rlib with `capi` enabled.
   - Name the test showing that standard error is empty after a contained panic, and the test
     showing a panic outside an entry point still reaches the previous hook.
   - If instead output is accepted for contained panics, that contradicts FR-018 and needs a
     spec change with a Gate 1 re-review.
2. **The plan's lock statement contradicts itself (VII-B; consistency with the delta, ADR and
   research).**
   - *Defect*: plan.md:83 says "Gurobi environment and model creation and freeing under one
     lock".
   - *Repair*: change it to environment creation and freeing only, as in plan.md:84-86, research

## Violations

- **V1. The column-count half of the too-large dimension case is neither mapped through C nor
  recorded as not expressible, and the contract's new validation order for it has no failing-input
  test (Development Workflow And Quality Gates, coverage; Principle II, "Every invariant checked
  before an FFI call MUST have a failing-input test"; review instructions "every requirement and
  success criterion is covered by tasks", "the analysis is honest").**
  - SC-006 (spec.md:481-484) covers every invalid-input case of the existing Rust failing-input
    tests that a C caller can express, with "too large". The Edge Cases (spec.md:287-288) name
    "row or column count beyond the 32-bit limit". The Rust test `t020_dimension_too_large`
    (tests/contract.rs:313-328) checks both: `TooLarge { what: "m" }` and `TooLarge { what: "n" }`,
    the latter with the comment "n is checked before the length of col_ptrs, so no huge array is
    needed".
  - Gate 2 review 5's repair asked for "rows and cols each `MAX_DIMENSION + 1`". T016
    (tasks.md:189-192) maps only the row case ("A with `rows` above 2³¹ − 1 and zero columns").
  - The column case is the one where the order matters for soundness. From C, `col_ptrs` has the
    declared length `cols + 1` (contract, `optsolver_csc`). With `cols` = 2³¹ the slice bound
    (`len · 8 ≤ PTRDIFF_MAX`) passes, so unless the C layer checks the column count before building
    the `col_ptrs` slice it would build a 16 GiB slice over caller memory. The new contract sentence
    (contract 132-133, "dimensions, then its arrays") promises that order, which makes the case
    expressible with a one-element `col_ptrs`; but no task tests it: T006's enumerated
    failing-input list (tasks.md:97-102) omits it, and T016 tests only rows (whose case needs no
    C-layer order for A's own arrays at all, since zero columns means a one-element `col_ptrs`).
  - implementation-review.md:60 claims SC-006 covers "the too-large dimension case".
  - **Repair** (tasks.md and implementation-review.md only): add the column case to T016 (A with
    `cols` = 2³¹ and a one-element `col_ptrs` → `OPTSOLVER_ERR_TOO_LARGE` naming the column count,
    before any environment and without reading `col_ptrs`), or record it as not expressible with the
    reason; and qualify the SC-006 row of the analysis accordingly.

- **V2. Principle numerals cited without the principle's name in the task list (XII-A, Descriptive
  Names, Not Codes: "The constitution's principle numerals are locators; where cited, the
  principle's name accompanies them").**
  - tasks.md:7 "(Principles II, XIV)"; 29, 51, 53 "(XV-C)"; 43 "IX-I"; 74 "VII-B"; 97 "XIV-D";
    116 "(VII-A)"; 202 "XIV-D, XV-C"; 229 "VIII"; also implementation-review.md:97 "Principle II
    gap". None carries the principle's name.
  - Gate 2 review 5 (O1) asked that the names be added when tasks.md was next edited; it was edited
    in `3f41782` without them. A clear rule of the constitution left unmet in the artefact under
    review cannot be treated as an observation without waiving it.
  - **Repair** (tasks.md and implementation-review.md only): add the principle's name beside each
    numeral (for example "(XV-C, A Guard Is Tested Against The Failure It Guards)"), or drop the
    numeral where the sentence already states the rule.

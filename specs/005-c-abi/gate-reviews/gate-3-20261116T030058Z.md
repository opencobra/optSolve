## Findings per principle

### I. Performance And Memory First — complies

- The input path is zero-copy. `borrow` (`src/capi/problem.rs:189-209`) wraps
  `slice::from_raw_parts`, and every input array goes through it (`with_problem`,
  `problem.rs:324-448`). The only copies are the cone list and the power-cone exponents. These
  are per-cone descriptors, which FR-003 allows.
- Output buffers are NaN-filled in place (`result.rs` `out_array`). Names are converted lazily
  (`result.rs:51-62`).
- Heap evidence: three post-repair bundles, iDopaNeuroC_problem_LP (m = 1344, n = 2942,
  nnz = 13748), N = 3 per path, all deterministic. The C peak equals the Rust peak:
  137 822 B Gurobi and 136 587 B MOSEK. The buffer-path peak is lower: 91 069 B and
  102 299 B.
- Environment reuse is shown by `t012::reuse_one_handle` (20 problems through one handle).
- Solver configuration audit: the only new parameter is `SoftMemLimit`, unset by default.
  - The mapping is documented in `src/options.rs:119-123` and in research R2 and R9.
  - It is applied in the single writer, `gurobi/params.rs` `apply`, with its rationale beside
    it.

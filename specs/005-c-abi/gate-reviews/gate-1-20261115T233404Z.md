## Findings per principle

### I. Performance And Memory First: no violation

### II. Testing, Benchmarks, And Behavioural Evidence: violation (V2)
- Two test tiers (FR-014).
- The comparison rule is implemented once in the shared test module (FR-014).
- The tolerances are tied to the verification report's solver tolerances, with a solver-grounded
  fallback (spec.md:106-115).
- The benchmark targets in SC-002 and SC-003 are on a corpus instance declared in `project.yml`
  (line 74).
- The pointer-identity test is the positive control (SC-002).
- Failing-input tests are required (SC-006).
- **V2: SC-005's "deterministic outcome" and N = 1 rest on a premise the vendor contradicts.**
  - SC-005 (spec.md:471-474) requires the memory-limit outcome for a limit "below the instance's
    requirement", with "(N = 1, deterministic outcome)". It fixes no thread count and no margin.
  - The Gurobi 13.0 `SoftMemLimit` entry, read 2026-11-15, says:
    - "SoftMemLimit is only checked at places where optimization can be terminated gracefully,
      so memory use may exceed the limit between these checks";
    - "Memory usage is also tracked across all threads. One consequence of this is that
      termination may be non-deterministic for multi-threaded runs."
  - The spec quotes the first sentence (spec.md:57-58) but draws no consequence from it, and it
    omits the second.
  - As written, a correct implementation can fail SC-005. On a toy instance whose need only just
    exceeds the limit, the solve can finish before a check point, or terminate differently from
    run to run when it is multi-threaded. The N = 1 justification therefore does not hold.
  - This is the defect class of review 2's N1, now in the memory-limit criterion.
  - User Story 3's Independent Test (spec.md:207-208) says "far below". SC-005 says only "below",
    so the two are inconsistent.
  - The same applies to XV-A (see below).
- Observation for the plan, carried from review 2: the C layer adds invariants (null pointers,
  sense characters, cone and option codes, a structure-size prefix below the minimum). Each needs
  its own failing-input test.
